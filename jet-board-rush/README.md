# JET BOARD RUSH — FROST RIDGE

ジェット付きボードで雪山を右へ滑り抜ける、オートスクロールの横スクロールアクション。
参照は『ロックマン8』のスノーボード面と、スーパーマリオの自動スクロール面。
1プレイは約 85 秒。依存は CDN の three.js だけで、`index.html` 単体で動きます。
**スマホ（横向き）対応。**

## 遊び方

プレイヤーは勝手に右へ進み続けます。できるのは **跳ぶ・伏せる・減速する** の3つだけ。

| | PC | スマホ |
| --- | --- | --- |
| ジャンプ | `↑` / `W` / `Space`（長く押すほど高い） | 画面右側をタップ（長押しで高く） |
| しゃがみ | `↓` / `S` | 押したまま下へスワイプ |
| 減速（後ろ向き） | `←` / `A` | 画面左端を押し続ける |
| ポーズ / 音 | `ESC` / `M` | 右下の ♪ |

ゲームパッドも使えます（A ボタン=ジャンプ、十字キー下=しゃがみ、左=減速）。

**画面の説明は最小限**にしてあります。操作は最初の3つの障害物が教えます
（跳ぶしかない柱 → 跳ぶしかない穴 → 伏せるしかないアーチ）。コインはジャンプの
軌道上に並んでいるので、取ろうとすると自然に正しい跳び方になります。
一度クリアするとヒント表示は出なくなります。

## 速度と難易度

速度は時間ではなく**進行度**で決まります（`STAGES[0].speed` の折れ線）。

| 進行度 | 0% | 30% | 60% | 100% |
| --- | --- | --- | --- | --- |
| 速度 | 8.8 m/s | 11.5 m/s | 14.4 m/s | 19.0 m/s |

序盤は障害物の間隔が広く、終盤ほど密度と切り替えの速さが上がります。
最高速では次の障害物までの猶予が約 1.2 秒しかありません。

**減速（後ろ向き）は速度を 0.62 倍にします。** 密集地帯の手前には黄色い予告サインが
立っていて、そこは減速しないと「伏せる→跳ぶ」の切り替えが間に合わない間隔に
なっています。ただし**氷結ゾーンではブレーキの効きが 42% まで落ち、逆に少し加速します**。
減速すると当然タイムは落ちるので、スコアとのトレードオフになります。

## ダメージ（超魔界村方式）

被弾しても即ミスにはなりません。**服が脱げてパンツ一丁**になり、脱げた服が後ろへ飛びます。
パンツ一丁でもう一度当たるとミス。穴に落ちた場合は一発でミスです。
残機表示はありません。**自分の見た目が残りHP**です。

コース上の赤い上着アイテムを取ると服が戻ります（服がある状態で取ると結晶5個ぶん）。

## コースの作り方（データ構造）

コースは**部品（CHUNK）を並べただけ**です。`CHUNKS` に部品を足して `STAGES[].seq` に
名前を並べれば、新しいコースができます。座標は部品内の相対 m。

```js
const CHUNKS = {
  //           長さ    穴 [開始, 幅]           障害物・敵・アイテム
  mix_a: {len:58, gaps:[[24,5.5]], ents:[
    {t:'low',   x:10, w:4, y:1.30},        // くぐる（頭の高さ 1.30m 以下）
    {t:'block', x:40, h:1.9, w:1.6},       // 跳ぶ（上面には乗れる）
    {t:'plat',  x:20, w:7, y:0.8},         // 飛び石の足場
    {t:'ice',   x:6,  w:48},               // 氷結ゾーン
    {t:'enemy', x:28, kind:'slider'},      // slider=地上 / flyer=頭の高さ
    {t:'coins', x:22, y:2.2, n:4, dx:2.6, arc:1.4},  // 弧を描く結晶列
    {t:'wear',  x:17, y:2.0},              // 服の回復
    {t:'sign',  x:1}, {t:'hint', x:4, icon:'brake'}, {t:'goal', x:32}
  ]}
};
```

`compile()` がこれを絶対座標のワールド（床・障害物・敵・アイテム）に展開します。
床は「部品の長さから穴を引いた残り」として自動生成され、隣り合う部品の床は結合されます。

### 難易度の検証について

跳躍距離は `v·t`（t は落差を考慮した滞空時間）で決まります。設計時は次を機械的に確認しました。

- すべての穴が「その地点の速度での最大跳躍距離の 57% 以下」に収まっていること
- 「跳ぶ→伏せる」のような**動作の切り替え**が、着地後 0.25 秒以上あってから来ること
  （減速ゲートと終盤だけは、意図的に**減速しないと間に合わない**間隔にしてある）
- 敵は近づくと自分から寄ってくるため、**実際に出会う位置**で穴や障害物と重ならないこと
- 柱の高さが跳躍の頂点（2.68m）に対して余裕を持つこと（最大 1.9m）

## 気候（climate）の差し替え

見た目とパラメータは `CLIMATES` に分離してあります。`CLIMATE_ID` を変えるだけで、
空・霧・地面・氷・障害物・木・遠景・粒子・BGM の音階まで丸ごと入れ替わります。
プロトタイプの実装対象は `winter` ですが、構造の見本として `summer`（灼熱の海岸）の
データも入っていて、`CLIMATE_ID = 'summer'` にすれば通しで遊べます。

```js
CLIMATES.winter = {
  sky:[…], fog:{…}, light:{…}, ground:{…}, ice:{…},
  block:{…, shape:'icicle'},   // 障害物の形（icicle / rock）
  tree :{…, shape:'pine'},     // 木の形（pine / palm）
  dust :{…, mode:'snow'},      // 粒子（snow / heat）
  music:{root:220, scale:[0,2,3,5,7,8,10], tempo:132}
};
```

## 技術メモ

- **three.js r128（CDN）1本のみ。** テクスチャも音も手続き生成で、外部アセットはゼロ
- 地形・木・障害物は 110m 区画ごとに**1メッシュへ焼き込み**。面ごとに色を持たせた
  自前のジオメトリビルダ（`GB`）で組み立てるので、テクスチャなしでも面が読める
- **ドローコール 26 / 三角形 4.5k** 前後。結晶は InstancedMesh、敵は近づいたときだけ生成
- 遠景の山は3層の視差スクロール。カメラ位置に対して層ごとに違う速さで無限に繰り返す
- カメラは**画面の横幅が常に 33m になる距離**を毎フレーム計算する。端末のアスペクト比が
  変わっても「先が見える距離」が変わらないので、スマホでも同じ難易度になる
- 当たり判定は AABB。障害物は「柱＝上面に乗れる」「アーチ＝伏せれば通る」の2種類だけ
- 音は WebAudio 合成。風とジェットは速度に追従し、BGM は進行度でレイヤーが増える
- スマホは縦向きを検出すると回転を促してポーズする。タッチは指ごとに役割
  （左端=減速／それ以外=ジャンプ、下スワイプでしゃがみ）を判定する

Playwright（Chromium）で自動プレイのボットを走らせ、コース全体を通せることを確認しています。

```bash

# → http://localhost:8712/jet-board-rush/
```
